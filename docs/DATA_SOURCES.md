# Data sources and use

This inventory separates data used by the current UI from data prepared for integration. The NASA records in `src/data/robotRecords.json` are the curated archive and source of the new story, photo, quiz, and worksheet drafts. The current mission screens still read `src/data/relics.json` through `src/data/missions.js`; P3 must connect the new archive before those records are the UI's source of truth.

| Dataset | Source URL | What we use | Exact method, caching, and fallback | Feature and agency |
|---|---|---|---|---|
| NASA Image and Video Library | [API](https://images-api.nasa.gov) · [Image pages](https://images.nasa.gov/) | Photo search results, image ID, title, description, date, center/credit, and image URLs. Canonical records also store a pinned NASA ID, visible credit, page URL, and alt text. | The current gallery calls `/search?q={query}&media_type=image&page_size={max*2}` from `src/services/nasaImages.js`; it keeps results in memory and `localStorage` for 7 days. Search failure returns an empty result. Remote image URLs are loaded from NASA's `images-assets.nasa.gov`; the gallery falls back from medium to thumbnail on image error. The curated pins and canonical records are not yet connected to the legacy nickname-based gallery lookup. API verification is saved in `data-pipeline/samples/pinned-photo-audit.json`. | Mission photo gallery; NASA. Individual media may have third-party credits and restrictions; use the per-image credit and NASA page, and check the page for rights exceptions. |
| JPL Horizons | [API guide](https://ssd-api.jpl.nasa.gov/doc/horizons.html) · [API](https://ssd.jpl.nasa.gov/api/horizons.api) · [Target lookup](https://ssd-api.jpl.nasa.gov/doc/horizons_lookup.html) | Earth-centered distance and one-way light-time / light-seconds for a target. Surface objects use parent-body IDs (Moon `301`, Mars `499`), so the display must say “distance to Moon/Mars,” not distance to an individual lander. | The server route requests vector ephemerides from center `500@399`, vector table 2, then computes distance from the returned XYZ vector. Per-target in-memory cache is 6 hours. On upstream failure it tries `server/src/data/distance-snapshot.json`; if unavailable, the client falls back to local legacy `relics.json` values and labels the result local/snapshot. The sampled observer-ephemeris JSON (quantities 20/21) and verified spacecraft lookups under `data-pipeline/samples/` are parser fixtures, not the server's live request format. `HORIZONS_TARGETS` is empty by default; P2 must configure target IDs and make the canonical records available to the API. | Still Talking distance display; NASA/JPL. Live operation requires P2 configuration. |
| NASA Deep Space Network Now | [Live DSN page](https://eyes.nasa.gov/apps/dsn-now/) · [JSON feed used by server](https://eyes.nasa.gov/dsn/data/dsn.json) | Current active spacecraft-to-dish links, spacecraft code, and feed timestamp. | The server requests the JSON feed and matches active signal target codes using `DSN_ROBOT_MAP`. Cache TTL is 60 seconds. If refresh fails after a successful fetch, the last cached response is returned with `stale: true`; with no cached response the server reports unavailable. If the API itself is unavailable, the client uses a local “awake” status approximation; that is not live DSN data. The XML sample and observed `SPP` mapping in `data-pipeline/samples/` are research fixtures; runtime uses JSON. `DSN_ROBOT_MAP` is empty by default and must be configured by P2. | Still Talking signal tracker; NASA. |
| NASA Moon Trek | [Moon Trek](https://trek.nasa.gov/moon/) · [Trek tile service guide](https://trek.nasa.gov/tiles/apidoc/trekAPI.html?body=moon) | LRO WAC global equirectangular Moon mosaic. | `data-pipeline/build-maps.mjs` downloads the z=2, 8×4 JPEG tile matrix from `https://trek.nasa.gov/tiles/Moon/EQ/LRO_WAC_Mosaic_Global_303ppd_v02/1.0.0/default/default028mm/{z}/{row}/{column}.jpg`, stitches it with Sharp, and writes local 2048×1024 and 1024×512 WebP derivatives. The committed `public/images/maps/manifest.json` loads the 2048 texture at runtime; no runtime map request/cache is needed. If the manifest or texture fails, the globe uses the locally generated procedural texture. | Moon globe; NASA data (LRO/LROC via NASA Trek). Credit and rights note: [map credits](../public/images/maps/CREDITS.md). |
| NASA Mars Trek | [Mars Trek](https://trek.nasa.gov/mars/) · [Trek tile service guide](https://trek.nasa.gov/tiles/apidoc/trekAPI.html?body=mars) · [USGS mosaic entry](https://astrogeology.usgs.gov/search/map/mars_viking_colorized_global_mosaic_232m) | Viking VIS global color equirectangular mosaic. | Same reproducible z=2, 8×4 tile process, using `https://trek.nasa.gov/tiles/Mars/EQ/Mars_Viking_MDIM21_ClrMosaic_global_232m/1.0.0/default/default028mm/{z}/{row}/{column}.jpg`; compressed local WebP derivatives are loaded via the map manifest. Procedural Mars texture is the fallback if local map loading fails. | Mars globe; NASA/JPL Viking imagery with USGS processing, served by NASA Trek. See [map credits](../public/images/maps/CREDITS.md). |
| NASA LRO / LROC | [LRO mission](https://science.nasa.gov/mission/lro/) · [LROC citation and terms](https://www.lroc.im-ldi.com/about/terms) · [NASA image of Vikram's site](https://www.nasa.gov/image-article/nasas-lro-observes-chandrayaan-3-landing-site/) | LRO WAC source data for the Moon Trek map and NASA's image of the Chandrayaan-3 Vikram landing site. | LROC data is used indirectly through the Moon Trek raster; the app does not call the LRO/LROC API. The Vikram record links the NASA.gov article and carries its NASA/GSFC/ASU credit. The image was not returned by the NASA Image Library API audit. | Moon globe and Vikram photo attribution; NASA. |
| NSSDCA and NASA mission/archive pages | [NSSDCA lunar landing sites](https://nssdc.gsfc.nasa.gov/planetary/lunar/lunar_sites.html) · [NSSDCA lunar missions](https://nssdc.gsfc.nasa.gov/planetary/lunar/apolloland.html) · mission-specific URLs in each record's `sources[]` | Launch, arrival, end/last-contact facts, object identity, landing coordinates, mission events, and kid facts. | These are cited static source pages, not a runtime API. P1 reviewed and transcribed facts into `src/data/robotRecords.json`; each record retains its source URL array. `docs/FACT_CHECK.md` flags disputed or approximate fields. The legacy `src/data/relics.json` is still the current UI fallback and has undated distance values; it must not be described as a current NASA feed. | Dossiers, story, maps, quiz, and worksheets once migrated; NASA/NSSDCA. |
| NASA science/mission pages, JPL mission pages, and NASA Technical Reports Server | [NASA mission index](https://science.nasa.gov/missions/) · direct per-record URLs in `src/data/robotRecords.json` and `docs/REFERENCES.md` | Additional mission dates, operations/end reasons, current status, rover/lander facts, and heritage/orbital-preservation context. | Static official pages and reports are read and cited directly; no live endpoint or automatic refresh is used. | Robot records and “Why did we leave it there?” content; NASA/JPL. |
| ISRO Chandrayaan-3 mission material | [ISRO Chandrayaan-3](https://www.isro.gov.in/ISRO_EN/Chandrayaan3.html) · [ISRO APXS paper / site coordinates](https://www.isro.gov.in/media_isro/pdf/APXS_CH3.pdf) | Vikram launch and landing context, landing site coordinates, sleep/contact-attempt context. | Static official ISRO source URLs are stored in the Vikram record. No ISRO image is used. NASA's LRO landing-site image is a separately credited NASA asset. Vikram is explicitly labeled `agency: "ISRO"`; do not present its mission data as NASA data. | Vikram dossier/story/quiz/worksheet; other-agency data (ISRO). |

## Sources not used

NASA SVS is not used for the shipped maps; both textures come from Moon Trek and Mars Trek. No NASA logo is used. The all-planets Solar Map uses the project's procedural textures and the values in `src/data/planets.js`; it does not use a NASA SVS planetary texture set.

## Visibility note

`src/data/planets.js` and `src/three/SolarMap.js` include the Sun, the Moon, and all eight planets. `src/three/SolarMap.js` camera-distance rules hide some labels until a body is zoomed/focused. That visual behavior is owned by P3 and outside this data-doc change; P3 should verify all eight planet labels can be reached and are not permanently clipped.
